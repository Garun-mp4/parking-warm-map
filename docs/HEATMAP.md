# Плавная тепловая карта

Выбранный пользователем [вариант от 14.10.2026](reference/approved-thermal.png): непрерывный сине-голубой-жёлто-оранжево-красный слой поверх видео, без постоянных границ и номеров мест. Второй вариант палитры — жёлто-красный. Оформление оболочки следует DESIGN.md; палитра данных явно изменена по запросу пользователя. [Исходная дизайн-система](DESIGN-source.md) сохранена отдельно.

## Данные и отображение

Для места вычисляется `занятое время / (занятое + свободное время) × 100%`. Неопределённые интервалы не становятся свободными. Покрытие показывает долю периода с определённым состоянием и выводится отдельно от занятости. Все веса относятся к реальному времени съёмки, а не к длительности ускоренного MP4.

В версии 7 `backend/heatmap.py` строит единое поле по **парковочным рядам**, вместо отдельных кругов или прямоугольников на каждом месте. Направление рядов определяется по ближайшим соседям с учётом поворота камеры. Области группируются по поперечному расстоянию и промежутку вдоль ряда. Большие разрывы не соединяются; единичное место сохраняет мягкий овальный контур.

У каждого ряда есть осевая линия через центры мест и плавная внешняя оболочка с закруглёнными концами. Толщина следует реальным размерам областей и ограничивается расстоянием до соседних рядов, чтобы оставить проезды прозрачными. Внутри оболочки цвет непрерывен, включая промежутки между соседними областями одного ряда. Это область **визуальной интерполяции**, а не утверждение о дополнительных наблюдениях между размеченными местами. В исходном примере автоматически выделены пять рядов: 18, 14, 12, 7 и 3 места.

Занятость интерполируется вдоль ряда монотонным `smoothstep`: в центре каждого места сохраняется его исходное значение, между двумя центрами получается выпуклая комбинация их значений. Нет суммирования плотности, превышения 100% или выдуманного синего ободка вокруг места со 100%. Между рядами значения не смешиваются. Полностью неизвестное место и ближайшая к нему половина промежутка показаны штриховкой; неизвестный конец не участвует в числовой интерполяции как нулевой.

Непрозрачность определяет отдельная оболочка ряда: плотная середина и мягкий край. Форма мягко сужается, а цвет ослабевает между удалёнными местами; расстояние нормируется на ширину места, поэтому результат не превращается в ровные полосы. Перекрытия оболочек и влияние мест объединяются максимумом, не усиливая цвет. Число мест, занятость и покрытие не управляют плотностью известной части маски. Параметры толщины, закруглённых концов, допустимого разрыва, влияния места и свободного промежутка между рядами находятся в общем конфиге.

Цвет выбирается один раз после интерполяции числовой занятости. Цветовая шкала строится в HSV по кратчайшему переходу оттенка, сохраняя насыщенность промежуточных цветов; используется общий шаг 0,1 процентного пункта (1001 цвет). RGB-слои соседних мест не накладываются друг на друга. Видео в тепловом режиме имеет насыщенность 10%, чтобы цвет кузова не менял смысл цвета данных. Браузерная легенда содержит 101 опорный цвет той же шкалы; PNG/MP4 используют ту же таблицу цветов. При масштабировании экспорта применяется premultiplied alpha, чтобы невидимые RGB-пиксели не создавали цветных кайм.

За пределами оболочек рядов альфа равна нулю. Размеченные полигоны сохраняются как области измерения и выбора мест. Это графическое обобщение измерений по местам, а не дополнительные попиксельные наблюдения или измерение температуры.

Шкала всегда **0–100%**, без растягивания к минимуму/максимуму конкретного видео. Поэтому полный день действительно загруженной парковки преимущественно тёплый. Проценты в карточках остаются точными значениями конкретных мест, а не результатом интерполяции цвета под курсором.

## Реализация

- `shared/heatmap.json` — общий источник RGB-якорей палитр, параметров геометрии/композиции, начальной непрозрачности и версии рендера для Python и React.
- `GET /api/runs/{id}/heatmap.png?start=…&end=…&palette=thermal|warm` — прозрачный PNG поля; нет картинок из генератора или подставленных значений.
- `HeatmapLayer.tsx` получает поле, декодирует его в Canvas и сохраняет при воспроизведении видео. Оно обновляется только при изменении результата, периода или палитры. Слой скрыт при загрузке новых данных, ошибки имеют кнопку повторения.
- SVG хранит невидимые области для выбора мышью, касанием и клавиатурой. Стрелки переключают места, Enter/Space закрепляют карточку, Escape закрывает. У фокуса — круглый маркер вместо рамки области.
- Регулятор 0–100% меняет непрозрачность Canvas; повторного анализа и изменения чисел нет. По умолчанию 70%: насыщенный цветовой центр читается отчётливо, а фото остаётся видимым. Начальное значение API и экспортов берётся из того же параметра.
- Плеер сохраняет исходное соотношение сторон, в том числе на мобильном экране и в fullscreen. Это намеренное отличие от широкого кадрирования в сгенерированном концепте: все размеченные места остаются видны.

Результат связан с ID анализа, его версией разметки и границами интервала. API сводки возвращает ID анализа; слой не смешивает новую разметку или новый диапазон со старой сводкой. Генератор кеширует до восьми неизменяемых RGBA-полей. Версия палитры входит в URL браузера и ключ MP4-кеша.

## Экспорт

PNG использует тот же генератор поля, выбранные палитру, непрозрачность, период и кадр плеера. Подписи на русском, легенда и покрытие встроены в изображение. MP4 содержит всю запись: в режиме тепловой карты поверх каждого кадра показана карта выбранного периода; в режиме «Занятость» — состояния текущего наблюдения. Времена кадра и периода подписаны отдельно. CSV сохраняет исходные числа по выбранному интервалу.

В MP4 добавлены полосы заголовка и легенды вне исходного кадра. Для примера это 1000×922, 42 секунды. Файл публикуется атомарно; кеш различает анализ, период, палитру, непрозрачность, режим и версию рендера.

## Проверка

Автотесты проверяют видимый синий для 0%, штриховку неизвестного, прозрачные проезды между рядами, непрерывность внутри ряда, сохранение значений в центрах, отсутствие суммирования плотности, повёрнутую камеру, отказ от соединения удалённых групп, мягкую границу, независимость непрозрачности от дубликатов, насыщенность, масштабирование альфа-слоя, границы API и выбор реального кадра при экспорте. Браузерный сценарий: `scripts/browser-heatmap.js` (нужен запущенный сайт и рассчитанный пример).

Сценарий выполняет реальные переключения, переходы времени, сохранение PNG/CSV/MP4, проверяет клавиатуру, совпадение Canvas с видео в fullscreen, мобильную карточку и восстановление после намеренно смоделированного HTTP 500. Сценарий не меняет разметку и не перезапускает модель. Детальный итог — в VALIDATION.md.
